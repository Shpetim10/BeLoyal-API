# Legacy concurrency, scale, and PostgreSQL audit

Scope: the current Java/Spring application and Liquibase schema were inspected for behavior with multiple application instances, a few hundred concurrent users, and PostgreSQL semantics. This is a static audit; no database was started and no source file was changed. Severity describes production risk. `keep` means the design is safe, `rewrite` means behavior or schema must change, and `delete` means the legacy mechanism should not survive the Ritema migration.

## Must fix before the Postgres migration

1. Resolve the legacy points-to-four-balance mapping and immutable event model before writing tables (findings 23, 25, 60-61).
2. Design UUIDv7 key conversion and foreign-key remapping for all 23 auto-increment tables (finding 8).
3. Choose `timestamp` versus `timestamptz` per temporal field and define timezone/backfill rules (finding 9).
4. Replace all `TINYINT` booleans/status values with explicit PostgreSQL types and conversions (finding 10).
5. Define canonical case behavior and backfill/deduplicate email, username, VAT ID, and manual codes before adding PostgreSQL unique indexes (findings 11-14).
6. Add direct non-null `business_id`, tenant-leading indexes, RLS policies, and restricted DB roles to every tenant-owned table (findings 21-22, 48-50).
7. Add database value constraints and missing foreign keys; repair orphaned or invalid legacy data before enabling them (findings 23-24).
8. Translate query-shaped indexes for PostgreSQL, including all FK-leading and hot composite/partial indexes (findings 32-37).
9. Remove MySQL driver/dialect/config and in-app Liquibase execution; create a new immutable plain-SQL Flyway baseline (findings 7, 19-20).
10. Rotate every committed credential/signing secret before using any migrated environment (finding 46).

## First ten fixes after

1. Make points expiry single-writer/idempotent with a distributed scheduler lock and locked/atomic database transition (findings 1-2, 66).
2. Replace Redis-authoritative token versioning and make refresh rotation single-use under concurrency (findings 15, 41, 47).
3. Put tenant identity in the authenticated principal/JWT, establish read-only `TenantContext`, and bind transaction-local RLS context (findings 48-50).
4. Close the concrete media, customer lookup, member-status, and guest-profile IDORs (findings 51-54).
5. Add client idempotency keys with PostgreSQL unique constraints/original-result replay to coupon purchase and staff consumption (findings 62-64).

7. Move uploads to S3-compatible object storage and remove public node-local serving (findings 6, 56).
